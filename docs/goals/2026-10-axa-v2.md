# Goal: AXA v2 — one design system, an inbox-first console, a first-class terminal

Written 2026-10-21 by the AXA commander after four parallel research and audit passes (web UX,
terminal UI, integrations, code audit of `main` at 8bab5e3). This file is the full spec; the `/goal`
condition at the bottom points here. Read it all before starting.

## Why

AXA works: sessions run, routine approvals are handled, the commander wakes itself. What's missing
is polish and coherence. The web console and the terminal app were built separately and it shows
(different status words, colors, features). Status polling blocks the server. There are no tests.
The aim of v2: **AXA should look and feel like one premium product in the browser, on the phone and
in the terminal, and cost less to run.**

What the user sees today (from screenshots, 2026-10-21):
- Web: shell sessions sit on "STARTING" forever (the terminal app says "shell"); the 🔔 button shows
  an empty box (missing glyph); every session appears twice (map card and sidebar card); large empty
  areas while the terminal is squeezed into the bottom half; generic header buttons
  (TERMINALS / INTEL / DETAIL / DEMO / CENTER).
- Terminal: recently cleaned up (tree sidebar, one header row, no activity strip) but no visual
  identity, no key discoverability after Ctrl-b, flicker on heavy redraws.

## Ground rules (non-negotiable)

- Work in a new git worktree: `git -C ~/axa worktree add ~/axa-v2 -b axa-v2` and only edit there.
  The live install is `~/axa` (main): never edit it, never touch `~/.axa`, the live console on port
  4747, or tmux socket `axa-4747`. Never run `axa stop` against the live console.
- Test consoles: `AXA_PORT=48xx AXA_HOME=$(mktemp -d) AXA_SUPERVISOR=0 node console/server.mjs`;
  stop them and `tmux -L axa-48xx kill-server` afterwards. Terminal-app captures: run `node bin/axa`
  against the test console inside `tmux -L axa-uitest new-session -d -x 120 -y 32 …` and
  `capture-pane -p`; also check 80x24.
- Keep AXA's style: zero-dependency plain Node ES modules and plain HTML/CSS/JS (no framework, no
  bundler). New npm packages only if MIT/Apache/BSD, small, and justified; credit in CREDITS.md.
- Never push or merge to main, never deploy, never send data to an outside service (any push
  integration ships **off by default** and is tested only against a local mock server). Don't
  change Windows Terminal settings or anything under `/mnt/c`; installers write to a path given by
  an env var in tests.
- Commits: `git -c user.name="Adrian Alvear" -c user.email="adrianalvear09@gmail.com" commit`,
  messages ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit per phase.
- Orchestrate with the `axa` skill: researcher before builders on anything new, builders in separate
  worktrees when they touch the same files at once, a reviewer on every phase's diff. Run the
  `verify` skill before calling a phase done.
- Stop and report (don't guess) if a phase needs a product decision not covered here.

## Phase 0 — Foundation: tests, structure, speed (do first)

Tests (`node --test`, folder `test/`, zero dependencies), at least these:
1. `lib/safety.mjs`: `redact` (keys, tokens, a secret split across a wrapped line), `oneWayDoor`
   (`npm publish`, `git push origin main`, `git push --force`, `sudo`, deploy CLIs, curl `-d` to a
   real host vs `localhost:4851`, quoted-only matches), `dangerousShell`, `cleanText`.
2. Session status state machine, extracted from `server.mjs` into `console/status.mjs` (pure):
   prompt → tool → Stop = done; verify-gate bounce stays working (Stop/VerifyGate in both orders);
   worker PermissionRequest = working+asking, waiting after 75s; AxaDecision escalate = waiting;
   UserAnswer; stuck after the in-flight timeout; shells report `shell`/idle, never "starting" forever.
3. Prompt parsing: `choicesOf` / `PERMISSION_RE` against fixture screen captures (numbered options,
   trust dialog, AskUserQuestion), `answerTerm` cursor moves.
4. `hooks/policy.mjs` and approver helpers via stdin (`cd` chains, tmux to AXA's socket vs a private
   socket, `~/.axa` access, project matching, `unquote` / `RUNS_TEXT`).
5. Server: 401 without cookie, 403 on a foreign Host, `/answer` 403 without the page/TUI headers,
   `/api/chains` validation (start the server on a temp port and home).

Structure (plain modules, behavior unchanged):
- `server.mjs` → `console/status.mjs` (track/statusOf/runs), `console/supervisor.mjs` (supervisor,
  chains), `server.mjs` keeps HTTP. `terminals.mjs` → split out `console/usage.mjs`, `console/gitinfo.mjs`.
- `index.html` → `index.html` + `console/ui/*.css|*.js` served by a static allow-list route.
- `tui.mjs` → `console/tui/` (`index`, `theme`, `sidebar`, `map`, `views`, `palette`, `overlays`, `events`).

Speed and correctness fixes found by the audit (each with a test or a measured before/after):
- Screen captures for status (`awaitingPermission`, `choicesOf`, pane width) move to one background
  refresher; `listTerms()`/`summary()` only read the cache. No `spawnSync` on any request path.
- Web console stops polling while the tab is hidden; terminal app polls with an in-flight guard and
  backs off when idle; prefer the SSE stream for changes.
- Terminal app: on a replayed `history` block, clear its derived state first (helpers, tallies,
  activity, feed) — today a console restart double-counts everything.
- Approver: cache the session goal (don't re-read 4 MB of events per request), skip the LLM for
  read-only tools, and cache decisions by normalized command per project for the session's life
  (never for one-way doors, never across projects).
- Prune `usageCache` on session close; cache failed transcript lookups longer; prune fired/failed
  chains after a day; keep an in-memory ring of recent events for SSE history instead of re-reading
  the file on every connect; cache vendor files.
- The supervisor's hourly wake limit shows a visible notice when hit (web and terminal).

## Phase 1 — One design system for web and terminal

- `console/theme.mjs` (shared): named themes as tokens → CSS custom properties (web), the xterm.js
  `theme` (embedded terminals, with `minimumContrastRatio: 4.5`), and the terminal app's roles
  (truecolor, quantized to 256 and to ANSI 16 when `COLORTERM` lacks truecolor; `NO_COLOR` = mono).
- Ship these themes (contrast checked: every role ≥ 4.5:1 on bg and panel):

  | Theme | bg | panel | text | dim | accent | ok | warn | bad |
  |---|---|---|---|---|---|---|---|---|
  | AXA HUD (default, current identity) | #04070b | #0b1520 | #cfe9f3 | #8aa6b4 | #4fd8ff | #5ef2c2 | #ffb547 | #ff6b7d |
  | Graphite (neutral dark) | #0f1115 | #171a21 | #e6e8ec | #98a0ad | #7aa2ff | #4cd694 | #f2b24c | #ff6b6b |
  | Paper (light) | #fbfbfa | #ffffff | #1b1f24 | #5a6470 | #0b5fd6 | #11713f | #8a5a00 | #b42318 |
  | Solar Night (warm dark) | #14110f | #1d1915 | #efe6dc | #a89a8b | #ffa94d | #8fd18a | #ffd166 | #ff7a6b |
  | High Contrast | #000000 | #0a0a0a | #ffffff | #c8c8c8 | #00e5ff | #3dff9a | #ffd400 | #ff5c5c |

  Plus "Terminal colors" for the terminal app (uses the user's own 16-color scheme, today's default
  there). Add a test that recomputes the contrast table from the theme file.
- One status vocabulary shared by both UIs (`console/look.mjs`): glyph + word + color role for
  needs you / stuck / working / done / ready / shell / starting / exited, used everywhere (cards,
  lists, tabs, titles, notifications). Never color alone.
- Web theme switcher (header and settings), "follow system light/dark", saved per browser; terminal
  app picks the same theme names. One setting changes both when the user chooses "sync".
- Typography: system UI font for text, a mono font for paths/ids/code (bundle nothing proprietary;
  JetBrains Mono is OFL if bundled), tabular numerals, a 4px spacing grid, compact/comfortable density.

## Phase 2 — Web console: inbox-first, premium, phone-ready

- **Home = "Needs you" + "While you were away".** A pinned strip of sessions waiting on the user with
  the question and tap-to-answer, then a timeline since the last visit (per-browser `lastSeen`):
  finished runs with one-line outcomes, verify-gate bounces, AXA's approvals/refusals, failures,
  links fired — each row opens the session, its diff or its run.
- The mission map stays (it's AXA's identity) but becomes one view, not the landing page, and stops
  duplicating the session list. Replace the header buttons with clear navigation: Home, Sessions,
  Map, Runs, Settings.
- **Command palette (Ctrl/Cmd-K)**: jump to a session, answer a prompt, open a diff, give a goal,
  link sessions, switch theme, open settings; plus keyboard parity with the terminal app (j/k, Enter,
  `?` help).
- Runs view: per-instruction timeline (steps, helpers, approvals, checks, result), the same data the
  terminal app's history uses.
- Cost meter: tokens and USD per session and per day where available (statusLine `cost` / telemetry
  if adopted in Phase 4), budget warnings.
- Motion rules: animate state changes only (150–200 ms crossfades, one flash for a new "needs you",
  a slow pulse only on working sessions); `prefers-reduced-motion` removes pulse and reactor spin.
- Designed empty, loading and error states ("All quiet · 3 idle · last event 4m ago").
- Fix the 🔔 glyph (inline SVG icons, no emoji in UI chrome) and the "STARTING" shells.
- Phone: bottom tabs (Home, Sessions, Terminal, More), approvals in a bottom sheet with ≥48px
  targets in the thumb zone, compact header orb instead of the reactor, keep the key bar above the
  keyboard via `visualViewport`, safe-area insets.
- PWA: manifest + service worker caching the shell, offline banner ("console unreachable · last
  seen …"). Works on localhost; document Tailscale Serve for phone access (don't set it up).

## Phase 3 — Terminal app: flicker-free, discoverable, beautiful

- Synchronized output (DEC 2026, detect with DECRQM `CSI ?2026$p`, harmless if unsupported) around
  every frame; keep per-row diffing; re-render a pane only when its headless terminal has new output;
  coalesce frames (≤ 30–60 fps). Remove the 250 ms forced redraw (animate from the same tick only
  when something is working).
- **Which-key popup**: ~400 ms after the prefix, a floating legend of the next keys grouped by
  purpose; per-view footer legends.
- Status bar with a mode chip (NORMAL / PREFIX / PALETTE / ZOOM / MAP), "⚠ N need you", focused
  session's branch, theme name, clock.
- Focus: accent rounded/heavy border on the focused pane, dim on others (plus a ▶ marker, not color
  alone). Braille spinner only for working sessions, shared render tick.
- OSC 8 hyperlinks for URLs and file paths in AXA's own panels (opt-out `AXA_NO_OSC8`).
- Grapheme-aware width (`Intl.Segmenter` + wide/emoji ranges) replacing the hand-rolled table; tests
  with ZWJ emoji and variation selectors. Optional Nerd Font icons via `ui.json` (never auto-detected).
- Memory: cap headless scrollback (~2k lines), dispose terminals for panes not on screen.
- `axa setup terminal`: writes a Windows Terminal JSON fragment (an "AXA" profile running `wsl axa`
  plus the current theme as a color scheme) to the Fragments folder — only when the user runs it;
  tests write to a temp dir via env var; UTF-8.
- Desktop notification when something needs the user and the window isn't focused: bell always,
  optional Windows toast through `powershell.exe` (opt-in in settings).

## Phase 4 — Integrations and efficiency

- **Commander digest tool** (`digest_sessions` in `mcp/axa-terminals.mjs`): per session state, last
  report, diff stat, failures, approvals since last call, from the event log — so the commander reads
  screens only when needed. Update `commander.md` to prefer it.
- **Stuck/looping detection** beyond the idle timer: same normalized tool call repeated N times,
  repeated policy denials or verify bounces, failure streaks → "looks stuck: <reason>", escalated to
  the user, never auto-killed.
- **Real cost data**: an `axa statusline` script (Claude Code statusLine) that shows AXA's state in the
  user's own Claude window and records each session's `cost.total_cost_usd` and context % into
  `$AXA_HOME`; the console shows USD and context. Handle `StopFailure` (rate limit, billing) as a
  visible state. Installing the statusLine into the user's settings is a documented manual step.
- **GitHub, read-only**: per-session PR and CI status via `gh` (`gh pr view --json`, `gh run list
  --json`) when `gh` is authenticated, shown on cards and in the terminal sidebar. Opening PRs is out
  of scope (one-way door).
- **Phone push (off by default)**: a notifier interface with an ntfy implementation (private random
  topic, only session name + short reason, never prompt text); tested against a local mock HTTP
  server only. The approver keeps "send data out" as a one-way door; this is user-configured output.
- **Approver measurement**: a script that replays past AxaDecision events from a test fixture (not
  the user's live log) against Haiku and Sonnet and prints agreement and latency; cap at 30 calls.
  Recommend, don't switch defaults.
- **Research spikes, write-up only** (in `docs/research/2026-10-v2-spikes.md`): does `claude agents
  --json` see AXA's tmux sessions (could replace screen scraping)? How does Claude Code's built-in
  auto mode compare with AXA's approver? Can `SendMessage`/`notify_when_idle` replace `link_sessions`?
  Recommendations only; no switch-over in v2.

## Out of scope for v2

Merging to main, deploying, changing the user's Windows Terminal or Claude settings, real push
services, opening PRs, Electron/desktop app packaging, multi-machine SSH.

## Verification (each phase, then all together)

- `node --test` passes; `node --check` on every changed file; the verify skill's PASS table.
- Performance: with 8 shell sessions on a test console, a script shows no event-loop stall over
  50 ms from status polling (measure with `perf_hooks.monitorEventLoopDelay` before/after), and the
  terminal app writes only changed rows (count bytes per idle second before/after).
- Screenshots (`node scripts/shot.mjs`): desktop 1440×900 and phone 390×844 of Home, Sessions, Map,
  Runs, Settings, an approval bottom sheet, for AXA HUD and Paper themes; reviewed and fixed.
- Terminal captures at 120×32 and 80×24: sidebar, which-key popup, palette, map, briefing, a waiting
  prompt bar, two-pane split; reviewed and fixed.
- A reviewer subagent approves each phase's diff (two reviewers for the approver, policy and
  `/answer` changes, both must APPROVE).
- README updated for every user-facing change; CREDITS.md for anything reused.

## Done when

All phases are implemented and verified as above on branch `axa-v2`, committed per phase, pushed with
`git push -u origin axa-v2` (never main), the spikes doc is written, and a final report lists: what
changed per phase, the verification table, before/after numbers, screenshots/captures paths, and
anything deferred with the reason.
