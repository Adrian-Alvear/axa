Yegge Gas Town (secondhand): Mayor + workers in worktrees/tmux, watchdogs, prime/handoff commands, merge queue, ~20 agents, "expensive as hell"; Klabnik: "aggressively not rigorous".
Huntley (read): Ralph loop, one task per loop, multi-agent "a red hot mess".
Anthropic (read): long-running agents need recoverable state (progress file, commits, init script, JSON feature list), one feature per session, agents declare victory early; multi-agent ~15x tokens, interdependent coding a poor fit; fresh-context read-only reviewer; background loops keep spending.
Would praise: one command center, who-needs-me, worktrees, verify gate + independent reviewer, only one-way doors escalate, handoff-based reviews, phone console.
Would criticise: too much machinery/animation; LLM approver + commander can fail quietly; notification volume; cost invisible; worktrees break dev servers/ports.
Lessons: design for review capacity (review queue, landable state, cap 3-8 workers); human-scheduled interruptions (digest/quiet, rank by blast radius); machine-readable handoff (progress file, feature list); stronger verification (end-to-end, no test deletion, fresh-context reviewer); show cost; shared state per worktree (ports, DBs, env files) or shared-folder mode; small deterministic rules first, narrow commander; close the learning loop (after a mistake, propose an AGENTS.md/tooling fix).
